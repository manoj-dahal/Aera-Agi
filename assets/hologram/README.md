# Hologram assets

Generated by `tools/meshgen`. Regenerate at any time:

```bash
python -m tools.meshgen --out assets/hologram --segments 128
```

Units are **millimetres**. Each `.obj` ships with a matching `.mtl` referencing
4K texture maps in `textures/`.

## Options

```bash
python -m tools.meshgen --detail 0.25      # finer triangles (mm edge length)
python -m tools.meshgen --only orb         # single asset
python -m tools.meshgen --segments 256     # denser character topology
python -m tools.meshgen --seed 42          # different orb displacement
```

## On "0.01 mm detail"

That figure was requested and is worth explaining rather than silently ignoring.

Sampling a 1.6 m character at 0.01 mm spacing implies roughly **16 billion
vertices** and a **1.7 TB** ASCII `.obj`. No renderer, game engine or DCC
application can open that; Blender becomes unusable in the low millions of
polygons, and real-time engines budget tens of thousands per character.

`--detail` is therefore clamped to a 0.05 mm floor, and passing anything smaller
prints a warning explaining why.

Detail at that scale belongs in **texture space**, not geometry. The generated
MTL files already reference 4K diffuse, normal and roughness maps: a 4096×4096
normal map across a 60 mm orb resolves about **0.015 mm per texel**, which
delivers the requested fidelity at a size that actually loads. That is how
production pipelines do it — sculpt high, bake to normals, ship low-poly.

## What these are

Clean **base meshes**: correct proportions, closed manifold surfaces, unit
normals, and spherical/cylindrical UVs ready for texturing. The characters have
anatomical joint spheres at the shoulder, elbow, hip and knee so limbs stay
connected under deformation.

They are **not** finished production characters. Faces have no modelled
features, hands have no fingers, and there is no rig or blendshapes. Those need
an artist. What is here is a solid starting point that loads anywhere.
