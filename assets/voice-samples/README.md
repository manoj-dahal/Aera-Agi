# Voice persona samples

Generated by `aera.voice.personas`, one file per persona and emotion:

```bash
python -c "
from pathlib import Path
from aera.voice.personas import ANIME_GIRL, ANIME_BOY, synthesize_wav
from aera.voice.engine import Emotion
for p in (ANIME_GIRL, ANIME_BOY):
    for e in (Emotion.NEUTRAL, Emotion.EXCITED, Emotion.SAD):
        synthesize_wav('Hello! I am AERA.', p, emotion=e,
                       path=Path(f'assets/voice-samples/{p.id}-{e.value}.wav'))
"
```

| File | Pitch | Notes |
|---|---|---|
| `anime-g-neutral.wav` | 255 Hz | Bright, light — pairs with the `anime-g` avatar |
| `anime-g-excited.wav` | 310 Hz | Higher and faster |
| `anime-g-sad.wav` | 224 Hz | Lower and slower |
| `anime-b-neutral.wav` | 145 Hz | Warm, steady — pairs with `anime-b` |
| `anime-b-excited.wav` | 167 Hz | |
| `anime-b-sad.wav` | 133 Hz | |

## What these are, and are not

**This is a formant synthesiser, not a text-to-speech engine.** The audio
carries each persona's pitch, pacing and lip-sync timing, so you can hear the
difference between the two characters and check that mouth movement lines up —
but it does not articulate words. You will hear a pitched, vowel-like voice,
not sentences.

That limit is not a design choice. A neural voice needs a pretrained model,
and every source for one (HuggingFace, GitHub release assets, the Piper CDN)
is unreachable from the build sandbox. `piper-tts` itself installs from PyPI
fine — only the model weights cannot be fetched.

## Getting real speech

Personas are engine-agnostic: each carries `engine_hints` for Piper, Coqui and
ElevenLabs. Register a backend and the same personas drive it —

```python
from aera.voice.personas import ANIME_GIRL
ANIME_GIRL.engine_hints["piper"]   # {'voice': 'en_US-amy-medium', 'length_scale': 0.94}
```

Implement `TTSBackend.synthesize` against your engine, pass it to
`VoiceEngine(tts=...)`, and pitch/speed/emotion mapping carries over unchanged.
